# Documentation : règles éditoriales

Les guides destinés au développeur sont placés sous docs/guides/<section>/, les notes de maintenance, ADR, incidents et procédures de release restent dans les autres dossiers de documentation GitHub. Ne pas ajouter de journal daté à un guide ; mettre à jour l'instruction concernée. Les anciens documents sont conservés comme historique et ne sont pas une seconde procédure d'installation.

Le parcours est validé par un développeur qui découvre SymSvel : installation CLI, création locale, code métier, module, mise à jour et production. Chaque guide décrit les fonctionnalités réellement supportées, avec commandes reproductibles. Les captures réelles des deux Setup restent à intégrer après CT ; ne pas fabriquer de visuels. La prise en charge généralisée des vendors tiers et le premier déploiement entièrement manuel sans CD ne doivent pas être annoncés comme disponibles.
